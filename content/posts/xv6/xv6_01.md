## sleep

xv6 위에서 유저 프로그램을 작성하는 첫 번째 연습이다. Unix의 `sleep` 명령처럼, 사용자가 지정한 tick 수만큼 대기하는 프로그램을 만든다. tick은 xv6 커널이 정의하는 시간 단위로, 타이머 칩의 인터럽트 간격이다.

파일 위치: `user/sleep.c`

{{% collapse summary="힌트" openByDefault=false %}}
- 시작 전에 [xv6 book](https://pdos.csail.mit.edu/6.1810/2025/xv6/book-riscv-rev5.pdf)의 Chapter 1을 읽는다.
- `user/` 아래의 다른 프로그램들(`echo.c`, `grep.c`, `rm.c`)을 참고하여 커맨드라인 인자가 어떻게 전달되는지 확인한다.
- `Makefile`의 `UPROGS`에 sleep 프로그램을 추가해야 `make qemu`로 컴파일된다.
- 인자를 빼먹었을 때 에러 메시지를 출력해야 한다.
- 커맨드라인 인자는 문자열로 전달되므로, `atoi`(`user/ulib.c` 참고)로 정수 변환한다.
- `pause()` 시스템 콜을 사용한다.
  - 커널 구현: `kernel/sysproc.c`의 `sys_pause`
  - 유저 헤더: `user/user.h`
  - 유저→커널 진입 어셈블러: `user/usys.S`
{{% /collapse %}}

{{% collapse summary="`sleep 10`을 치면 발생하는 전체적인 흐름" openByDefault=false %}}

`sleep 10`을 치면 어떻게 돌아가는지 파악하기 위해 `user/sh.c`를 뜯어 보면 다음과 같은 흐름으로 동작한다.

1. 쉘(`sh`)이 사용자 입력인 `sleep 10`을 read
2. 쉘이 `fork()`로 자식 process를 만듦
3. 자식 프로세스가 `exec("sleep", arvs)`를 호출
4. `sleep.c`의 ELF가 메모리에 로드되고, `sleep.c`의 `main`으로 점프
5. `main(argc, argv)`로 호출
6. `sleep.c`의 `main` 동작 <- 우리가 작성 해야할 곳
7. 쉘(부모)가 `wait()`으로 자식 프로세스 종료를 기다림.

## sixfive

시스템 콜 `open`과 `read`, C 문자열 처리, 텍스트 파일 파싱을 연습하는 과제다.

입력 파일에서 모든 숫자를 찾아, **5 또는 6의 배수**인 것만 출력한다. 숫자는 십진 숫자의 연속이며, 구분자는 `" -\r\t\n./,"` 문자열에 포함된 문자들이다. 즉, `"xv6"`에서 `6`은 숫자로 인식되지 않지만, `"/6,"`에서 `6`은 숫자로 인식된다.

### 실행 예시

{{< terminal >}}
$ sixfive sixfive.txt
5
100
18
6
$
{{< /terminal >}}

{{% collapse summary="힌트" openByDefault=false %}}
- 입력 파일을 한 글자씩 읽는다.
- `strchr`(`user/ulib.c`)를 사용해 현재 문자가 구분자인지 판별할 수 있다.
- 파일의 시작과 끝도 암묵적인 구분자로 취급한다.
{{% /collapse %}}

### 풀이
<!-- TODO: 구현 코드 및 설명 추가 -->
{{% collapse summary="풀이" openByDefault=false %}}
C언어 시간 때 배운 {{< memo "strtok" "문자열과 구분자가 인자로 주어질때, 토큰을 반환하는 함수" >}} 함수가 있다고 생각해보자.

그렇다면 우리가 해야할 것은 다음과 같다.
1. 파일을 연다.
2. 파일을 읽어 buf에 저장한다.
3. buf에 저장된 문자열을 strtok로 Tokenize한다.
4. Tokenize한 문자열이 숫자라면, 5의 배수 or 6의 배수인지 체크하여 출력 여부를 결정한다. (알파벳같은게 섞여 있으면 안됨.)
5. 1-4를 주어지는 여러 개의 파일마다 반복한다.

코드로 보자.
```
#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"
#include "kernel/fcntl.h"
#define NULL ((void *)0)


char* strtok(char *str, const char* delimeter) {
    static char *last;

    if (str != NULL) last = str;
    if (last == NULL || *last == '\0') return NULL;

    while (*last && strchr(delimeter, *last)) last++;
    if (*last == '\0') return NULL;

    char *token_start = last;

    while (*last && !strchr(delimeter, *last)) last++;

    if (*last != '\0') {
        *last = '\0';
        last++;
    }

    return token_start;
}

int isDigit(char* s) {
    if (s == NULL || *s == '\0') return 0;
    for (int i = 0; s[i] != '\0'; i++) {
        if (! ('0' <= s[i] && s[i] <= '9')) {
            return 0;
        }
    }
    return 1;
}

int isTargetNumber(int val) {
    return (val % 5 == 0 || val % 6 == 0);
}

void printsixfive(char *buf) {
    const char *delim = " -\r\t\n./,";
    char *token = strtok(buf, delim);

    while (token != NULL) {
        if (isDigit(token)) {
            int val = atoi(token);
            if (isTargetNumber(val)) {
                printf("%d\n", val);
            }
        }
        token = strtok(NULL, delim);
    }
}

int main(int argc, char *argv[]) {
    if(argc < 2){
        fprintf(2, "Usage: sixfive files...\n");
        exit(1);
    }
    for (int i = 1; i < argc; i++) {
        int fd = open(argv[i], O_RDONLY);
        if(fd < 0){
            fprintf(2, "sixfive: cannot open %s\n", argv[i]);
            close(fd);
            exit(1);
        }
        char buf[512];
        int n = read(fd, buf, sizeof(buf));
        if (n > 0) {
            printsixfive(buf);
        } else {
            fprintf(2, "sixfive: cannot read %s\n", argv[i]);
            close(fd);
            exit(1);
        }
        close(fd);
    }
    exit(0);
}
```

## memdump

C 포인터를 깊이 연습하는 과제다. 시작 전에 K&R(The C Programming Language, 2nd Edition)의 섹션 5.1~5.6, 6.4를 읽는 것을 권장한다.

`user/memdump.c`에 `memdump(char *fmt, char *data)` 함수를 구현한다. 이 함수는 `data`가 가리키는 메모리의 내용을 `fmt` 문자열이 지정하는 형식에 따라 출력한다. 포맷 문자열의 각 문자는 데이터의 연속된 부분을 어떻게 출력할지 결정한다. 예를 들어, 여러 필드를 가진 C 구조체를 포맷 문자열로 출력할 수 있다. 포맷 문자는 다음과 같다.

| 포맷 | 크기 | 동작 |
|------|------|------|
| `i` | 4바이트 | 32비트 정수, 10진수 출력 |
| `p` | 8바이트 | 64비트 정수, 16진수 출력 |
| `h` | 2바이트 | 16비트 정수, 10진수 출력 |
| `c` | 1바이트 | 8비트 ASCII 문자 출력 |
| `s` | 8바이트 | 64비트 포인터가 가리키는 C 문자열 출력 |
| `S` | 나머지 전부 | 나머지 데이터를 null 종료 C 문자열로 출력 |

{{% collapse summary="풀이" openByDefault=false %}}

`memdump`함수는 `fmt`의 각 포맷에 따라, `data`를 출력해야한다.

그냥 `fmt`의 크기만큼 loop를 돌면서 printf를 하면된다.
포맷 변환은 `user/printf.c` 파일을 통해 찾아 보았다.  
코드는 다음과 같다.



```c {title="memdump.c - memdump(char *fmt, char *data)"}
void
memdump(char *fmt, char *data)
{
  // Your code here.
    char *p = fmt;
    char *q = data;

    while (*p != '\0') {
        switch (*p) {
            case 'i':
                printf("%d\n", *(int *)q);
                q += 4;
                break;
            case 'p':
                printf("%lx\n", *(uint64 *)q);
                q += 8;
                break;
            case 'h':
                printf("%d\n", *(uint16 *)q);
                q += 2;
                break;
            case 'c':
                printf("%c\n", *(char *)q);
                q += 1;
                break;
            case 's':
                printf("%s\n", *(char **)q);
                q += 8;
                break;
            case 'S':
                printf("%s\n", q);
                break;
        }
        p++;
    }
}
```

## find

경로명, 디렉토리, 시스템 콜 `open`/`read`/`fstat`을 탐색하는 과제다.

Unix의 `find` 명령의 간단한 버전을 구현한다. 디렉토리 트리에서 특정 이름을 가진 모든 파일을 찾는다.

파일 위치: `user/find.c`

{{% collapse summary="힌트" openByDefault=false %}}
- `user/ls.c`를 보면 디렉토리를 읽는 방법을 알 수 있다.
- 재귀를 사용해 하위 디렉토리로 내려간다.
- `"."`과 `".."`으로는 재귀하지 않는다.
- `make qemu`를 실행할 때마다 새 `fs.img`가 생성되어 이전 파일이 사라진다. 이전 파일 시스템을 유지하려면 `make qemu-fs`를 사용한다.
- C 문자열 비교는 `==`가 아니라 `strcmp()`를 사용한다.
- `Makefile`의 `UPROGS`에 추가한다.
{{% /collapse %}}

### 실행 예시

{{< terminal >}}
$ make qemu
...
init: starting sh
$ echo > b
$ mkdir a
$ echo > a/b
$ mkdir a/aa
$ echo > a/aa/b
$ find . b
./b
./a/b
./a/aa/b
$
{{< /terminal >}}

## exec (-exec 옵션을 find에 추가)

`fork`, `exec`, `wait` 시스템 콜을 연습하는 과제다.

`find`에 `-exec cmd` 옵션을 추가한다. find가 파일을 찾을 때마다 파일 이름을 출력하는 대신, `cmd file` 명령을 실행한다.

### 실행 예시

{{< terminal >}}
$ find . wc -exec echo hi
hi ./wc
$
{{< /terminal >}}

여기서 실행되는 명령은 `echo hi`이고, 찾은 파일이 `./wc`이므로, 실제로 실행되는 것은 `echo hi ./wc`이다. 출력은 `hi ./wc`.

{{% collapse summary="힌트" openByDefault=false %}}
- `fork`와 `exec`로 각 파일에 대해 명령을 실행한다. 부모는 `wait`으로 자식이 완료되길 기다린다.
- `kernel/param.h`에 선언된 `MAXARG`가 argv 배열을 선언할 때 유용할 수 있다.
{{% /collapse %}}

### 테스트

{{< terminal >}}
$ make qemu
...
init: starting sh
$ sh < findtest.sh
$ echo DONE
$ $ $ $ $ hello
hello
hello
$ $
{{< /terminal >}}

`$`가 많이 출력되는 이유는 xv6 셸이 파일에서 명령을 읽고 있다는 것을 인식하지 못하고, 매 명령마다 프롬프트(`$`)를 출력하기 때문이다.
